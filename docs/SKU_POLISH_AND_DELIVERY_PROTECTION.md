# SKU 识别、自动擦亮、发货保护与仓库范围

本次修改位于 XianYuAssistant-master。参考 xianyu-super-butler 的卖家 SKU 搜索、买家详情备用识别、擦亮接口和发货保护规则，接入本项目现有 Java 后端、Vue 页面及 SQLite 数据库。

参考源码版本：23Star/xianyu-super-butler，提交 e91a3ec155f90dddd06b1d93e0ad6580a841c332。

## 1. SKU 多规格发货

进入「自动发货」→选择账号和商品→「SKU 多规格识别」→「识别 SKU（卖家接口）」。卖家接口没有返回规格时，可以手动点「尝试买家接口」。遇到验证、令牌或风控错误时先处理账号状态，再等待冷却结束。

识别成功后选择每个规格，分别填写文本或绑定卡密仓库，并逐项保存。所有要出售的规格都配置好后再开启商品自动发货。存在规格发货规则时，未知或没有配置的 SKU 会停止发货，不会使用默认内容混发；多件购买继续按实际购买数量预留卡密。

- 兼容 skuId / inventoryId、actualValueText / valueText / value、properties / propertyList、嵌套详情响应。
- SKU ID 作为字符串保留，避免丢失前导零或大整数精度。
- 仅接受当前商品，拒绝卖家搜索返回的其他商品；不混入详情中的推荐商品规格。
- 空响应和识别失败保留原有规格；商品管理的零个已识别规格显示「未识别」，不再误显示为 1。
- 普通请求间隔 10 秒；某个来源失败后该来源冷却 5 分钟。风控类错误暂停该账号的两种来源 5 分钟。
- 有效 Cookie 和平台接口权限仍是识别的前提，无法保证每个账号都能获得平台 SKU 数据。

## 2. 自动擦亮

进入「运营与发货保护」→「自动擦亮」，选择账号，开启开关并保存。

间隔允许 1–720 小时，默认 24 小时。首次开启后由后台排程执行；每轮结束后按设置间隔安排下一轮，重启后继续使用已保存的时间。只处理当前账号在商品管理中已同步的在售商品。商品之间间隔 1 秒，遇到平台请求失败停止本轮；页面展示上次、下次时间和每件执行结果。

「立即擦亮」需要先开启并保存，正在运行时不可再次排队，距离上次开始不足一分钟不可手动重跑。关闭开关会停止后续商品，已发出的请求仍会完成。最多保留每个账号最近 2000 条记录。

## 3. 发货保护和黑名单

进入「运营与发货保护」→「发货保护」：

- 黑名单：按买家数字用户 ID 精确匹配，可设置所有账号通用或当前账号专用，也可仅限制某个商品。
- 买家被评价数：平台返回的被评价总数小于或等于设置阈值时暂停发货。
- 当前账号重复购买：买家在当前账号存在其他有效历史订单时暂停。
- 跨账号重复购买：买家在本系统任意账号存在其他有效历史订单时暂停。
- 待确认收货：买家在当前账号的待收货订单数量达到阈值时暂停。
- 可设置只统计同一商品，以及豁免商品 ID。豁免不绕过黑名单。

信用、重复购买、待收货保护默认关闭。黑名单检查默认开启，但没有匹配的启用记录时不拦截。

历史订单保护以本系统已经记录、带买家 ID 的订单为范围；不会主动导入账号全部历史订单。检查时重新向平台核实历史订单状态，排除当前订单、待付款、取消/关闭、退款中的订单。平台状态未知或查询失败时暂停发货，核实后可从发货记录重试。

检查在新卡密预留和内容发送之前执行，重试已经预留内容的订单也重新检查。命中后不会自动关闭平台订单；已经发送的卡密不能撤回，已经预留的内容仍保留用于后续重试。

## 4. 通用或账号私有卡密仓库

「卡密仓库」→新建时选择仓库范围；已有仓库通过「仓库设置」修改。

- 账号私有：只有所属账号的商品可绑定并出库。
- 所有账号通用：各账号可绑定同一仓库，使用同一份库存，使用记录保留实际发货账号。
- 通用仓库改成私有或更换私有所属账号前，必须先解除其他账号的商品绑定；后端也会拒绝不符合范围的发货配置。
- 旧仓库升级后自动保留为 PRIVATE（账号私有）。卡密备份导入导出包含范围字段。

## 5. 更新软路由镜像

这些修改需要构建新镜像后才会出现在软路由上。只重启旧容器不会更新程序。

1. 将修改后的源码上传自己的 GitHub 仓库，包括新增文件和删除的旧前端构建文件；不要上传数据库、Cookie、日志。
2. 在仓库 Actions 中运行已有的「Publish x64 Docker image」流程，等待成功。
3. DockerMan 拉取你自己的同名镜像，例如 ghcr.io/wenzge/xianyu-assistant-xiugai:latest。
4. 停止旧容器，并使用新镜像重新创建/替换容器，保留原有数据库挂载、日志挂载和端口设置。建议停容器后先复制数据库目录备份。
5. 新版启动会自动新增表和 scope 字段，原商品、发货配置及库存保留。刷新浏览器后可见新入口。

也可上传 deploy/dockerman 目录，使用其中新打包的 app.jar 和 Dockerfile 在软路由本地构建。
